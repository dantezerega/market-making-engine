# Interactive web app (Next.js)

TypeScript port of the Python model (`as_model/`) + vendored LOB sim
(`lob_sim/`), run entirely server-side in Vercel serverless functions —
no Python runtime needed in production.

- `src/lib/` — model.ts (closed-form AS formulas), rng.ts (seedable PRNG),
  orderbook.ts (matching engine, ported from `lob_sim/orderbook.py`),
  simulation.ts (OU price process + order flow, ported from
  `lob_sim/simulation.py`), calibration.ts (sigma/k/A estimation, ported
  from `as_model/calibration.py`), engine.ts (AS/naive MM tick loop,
  ported from `as_model/engine.py`), analytics.ts (markout + inventory
  risk metrics, ported from `as_model/analytics.py`), sweep.ts (gamma
  sweep, ported from `as_model/sweep.py`).
- `src/app/api/simulate/route.ts` — POST: runs an AS session + naive
  baseline session, returns time series + metrics.
- `src/app/api/sweep/route.ts` — POST: runs the gamma sensitivity sweep.
- `src/app/page.tsx` — interactive dashboard (parameter sliders, live
  charts via Recharts, head-to-head metrics table).

This is an independent re-implementation of the same formulas/logic as
the Python reference in `../as_model` and `../lob_sim` — verified to
produce the same qualitative results (AS reduces inventory variance,
improves P&L, on the same background flow process). It is not
generated by transpiling the Python; it's a manual TS port so it can
run as a Vercel serverless function without a Python runtime.

## Local development

```bash
npm install
npm run dev       # http://localhost:3000
```

## Deploy to Vercel

```bash
npm install -g vercel   # if not already installed
vercel                   # follow prompts, or:
vercel --prod
```

Or connect the GitHub repo directly at vercel.com/new — it auto-detects
Next.js, no environment variables or database required (no persistence
in this version; every request runs a fresh in-memory simulation).
